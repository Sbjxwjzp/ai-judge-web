LLM INTEGRATION

大模型集成：选型、流式、Prompt 与稳定化

AI 技术方案
选型理由

OpenAI 兼容抽象层

统一 chat/completions 接口，baseURL 可配，DeepSeek / 智谱 / 通义 / Moonshot 一键切换； 评审环境可选用任意国内可用模型，规避网络依赖。

集成方式

SSE 流式输出

深度锐评逐 token 渲染（打字机效果），思考过程可视化； 非流式 JSON 模式用于需要结构化解析的场景（response_format）。

Prompt 设计

角色 + 铁律 + 结构

资深评审官角色设定；铁律（不虚构数据 / 只评当前轮 / 输出合法 JSON）； 输出结构固定为 summary + asks，解析失败自动降级。

稳定可控

超时 + 重试 + 降级

45s 超时、网络错误自动重试一次、失败返回 null → 界面回退规则引擎版本， 演示现场不会因 API 抖动而中断。

输出稳定性策略：温度 0.35 + JSON 模式 + 结构校验 + 降级兜底，同一回答多次生成结构一致。

MULTIMODAL

多模态：语音输入（Web Speech API）

AI 技术方案
实现

浏览器原生语音识别

SpeechRecognition / webkitSpeechRecognition，zh-CN 普通话， 连续识别 + 中间结果；识别文本自动追加到回答输入框。

降级

能力检测

不支持语音识别的浏览器自动隐藏麦克风按钮，不影响核心质询流程； 识别失败提示错误并停止，可重试。

体验

贴合答辩场景

选手可以用嘴演练答辩，语音转文字直接提交， 比打字更接近真实答辩节奏，AI 锐评照常给出追问建议。

成本

零第三方依赖

不引入语音服务 SDK，无额外费用、无数据外传； 与"本地优先"的产品原则一致。

多模态设计取舍：现阶段以语音输入作为多模态入口（浏览器原生、零成本）， 为后续接入答辩录音分析、上传材料 OCR 等模态预留扩展位。

INNOVATION

创新点：技术 × 应用 × 交互

创新点说明
技术 01

规则引擎 × LLM 混合评审

决策与生成分离：追问链、评分、风险由确定性规则引擎负责， LLM 只做内容增强——可解释、防幻觉、可降级。

技术 02

本地 RAG 对齐官方标准

赛题评分标准做知识库、浏览器端词频检索、每轮锐评自动注入， 零依赖实现检索增强生成，评审意见落到官方考察点。

技术 03

Agent 自主工具调用

深度评审报告由 LLM 自主决定调用"查知识库 / 评分表评估"， Function Calling 两轮对话，真实 Agent 工作流。

应用 01

答辩前压力测试

把"没人帮挑毛病"变成"AI 连续压测"， 输出逐条可执行的改进清单，直接进答辩准备。

应用 02

数据红线产品化

不虚构数据写入产品铁律：缺失即标注"待验证"， 引导选手用"目标 / 计划测试"的正确答法。

应用 03

追问链交互

回答完整就深入一层、有漏洞就针对缺口—— 不是随机提问，模拟真实评委的追打节奏。

总结

一个可验证的 AI Native 应用

从真实痛点出发，用 Vue 3 + TS 构建完整前端工程， 以"规则引擎 + LLM + RAG"三层架构实现 AI 深度集成， 配齐测试、性能与安全工程化，所有结论可复现。

展望 1

多模态扩展

答辩录音 / 录屏分析（转写 + 追问）、上传材料 OCR 提取证据， 从语音输入扩展为"答辩全流程 AI 教练"。

展望 2

知识库可插拔

赛题知识库按 JSON 配置化，可切换不同比赛 / 评审标准， 从一个比赛工具变成通用"答辩教练"平台。

展望 3

端侧推理

接入 Transformers.js / WebGPU 做本地小模型兜底， 进一步兑现"端云协同"的技术路线。

社会价值：降低大学生创新创业项目的"答辩信息差"—— 让每一支队伍在上场前，都有一位不辞辛劳、不讲情面、不虚构数据的 AI 刁钻评委。
